# innen v0.10.1

The structure gate added in v0.10.0 could not detect its own broken baseline.

## Fixed

`scripts/check-structure.sh` shipped with a baseline that was not valid JSON.
Entries were joined without commas, so `json.load` raised `Expecting ',' delimiter`
at line 6. Two entries were stale: `crates/innen-core/src/parity.rs` had been
deleted by that same release, and `crates/innen-core/src/artifact/ledger.rs`
duplicated `artifact.rs`.

The gate could not notice either. It grepped the baseline for a filename instead
of parsing it, so a malformed baseline silently degraded to "no baseline entry"
— the exact state the gate exists to catch.

`scripts/check-structure.py` replaces it:

- the baseline is parsed with `json.loads`, and malformed JSON fails closed;
- an entry whose file no longer exists, or that is no longer over budget, is a
  **failure**, so recorded debt cannot outlive its own fix;
- an oversized file with no entry is a failure;
- internal `Task N` markers outside the legitimate `NodeType::Task` and
  `"type": "Task"` uses are a failure;
- file discovery lives in one function, and the baseline was generated by
  importing it. The previous generator and the gate disagreed about directory
  depth and therefore about 9 files, so the reported total of 24 was wrong; the
  real figure is 23.

## Verification

Each failure mode was injected and observed:

| Injected defect | Result |
| --- | --- |
| Malformed baseline JSON | exit 1, reports the parse error |
| Baseline entry for a deleted file | exit 1, `no longer exists; remove it` |
| 500-line file with no entry | exit 1 |
| `Task 9` marker | exit 1, with file and line |
| Clean tree | exit 0, `97 files` |

rustfmt, the structure gate, strict Clippy, and the locked workspace suite are
green for the release commit on macOS arm64 and Linux x86_64.
